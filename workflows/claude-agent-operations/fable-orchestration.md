# Fable 오케스트레이션

이 시스템은 AI를 많이 부르는 방식이 아니라, 판단 비용이 큰 구간과 반복 실행 구간을 나눠 쓴다. Claude Code에서 Fable이 켜져 있을 때 적용하는 현재 로컬 프로필을 기록한다.

| 역할 | 현재 프로필 | 맡길 일 | 산출물 |
| --- | --- | --- | --- |
| 기획·심층 판단 | `deep-reasoner` · Claude Opus 5.1 · max | 카드 3개 선택, 상충하는 지표 해석, 편집 우선순위 | 뉴스별 주장·근거·버릴 후보 |
| 빌더 | `executor` · Claude Opus 5.0 · xhigh | 템플릿 수정, 렌더링, 오류 수정, 시각 검수 | 변경 파일·검증 결과 |
| 실행 보조 | `runner` · Claude Sonnet 5 · medium | 파일 탐색, 명령 실행, 이미지 크기·ZIP 확인 | 짧은 사실 결과 |

위 모델 이름과 effort는 현재 운영 설정이다. 환경이 달라지면 설정을 다시 확인하고, 문서에 적힌 이름을 실제 실행 모델이라고 추정하지 않는다.

## 한 주의 분배

```text
고급 기획: 후보 5~8개 → 검증할 3개·판단 기준 확정
                         ├─ 국내 지표 원문 확인
                         ├─ 해외 지표 원문 확인
                         └─ 이전 카드의 색상·기간 확인
Opus 빌더: 확정 사실 → data.js → PNG 3장 → 시각 검수 → ZIP
```

기획 단계는 한 번의 깊은 판단으로 끝낸다. 이후 빌더는 이미 확정한 숫자·기간·문장 경계 안에서 작업한다. 이 분리가 같은 원문을 여러 에이전트가 다시 읽는 토큰 낭비를 막는다.

## 병렬 처리 규칙

- 독립된 출처 확인, 렌더 결과 검수, ZIP·이미지 크기 확인은 동시에 한다.
- 편집자가 확정하기 전의 후보 판단과 `data.js` 수정은 병렬로 섞지 않는다.
- 각 에이전트는 URL, 사실, 불확실성, 결론만 돌려준다. 원문 전체를 대화에 반복하지 않는다.
- 한 파일의 최종 편집자는 한 명이다. 결과를 합칠 때만 메인 에이전트가 확인한다.

## 토큰을 쓰는 기준

| 고비용으로 처리할 일 | 짧게 처리할 일 |
| --- | --- |
| 수치 충돌, 정책 적용일, 생활 영향의 인과 경계, 시각 구조 변경 | 파일 목록, 숫자 대조, 렌더 명령, 이미지 크기, ZIP 확인 |

모델이 만든 초안은 의견이고, 원문 수치와 렌더된 PNG는 검증 대상이다. 카드의 신뢰도는 모델 이름보다 이 두 가지를 끝까지 대조하는 과정에서 나온다.
